# SECURITY

> Trust is nice.
>
> Verification is better.

The arena is built around competition.

Competition attracts attention.

Attention attracts attackers.

Security is therefore not a feature.

Security is part of the product.

---

# 🛡 SECURITY PHILOSOPHY

The objective is simple:

Protect:

- Players
- Wallets
- Tournament integrity
- Reward infrastructure
- Protocol operations

While keeping the arena accessible and transparent.

The goal is not perfect security.

The goal is making attacks difficult, expensive and detectable.

---

# 🔑 WALLET SECURITY

Let's start with the obvious.

## WRAITH WILL NEVER ASK FOR YOUR SEED PHRASE.

Not on X.

Not in Discord.

Not in Telegram.

Not on the website.

Not anywhere.

Ever.

If somebody asks for:

- Seed phrase
- Recovery phrase
- Secret phrase
- Private key

It is not Wraith.

---

# ✅ WALLET AUTHENTICATION

Players may authenticate ownership of a wallet through cryptographic signatures.

This allows the arena to verify:

> "This wallet belongs to this player."

Without requiring access to:

- Private keys
- Recovery phrases
- Secret information

Important distinction.

The arena may verify ownership.

The arena should never require custody.

---

# 🚫 WHAT WRAITH WILL NEVER DO

Wraith will never:

- Ask for a seed phrase
- Ask for a private key
- Request wallet recovery information
- Request direct wallet access
- Ask users to transfer tokens for verification
- Ask users to reveal sensitive credentials

If someone claiming to be Wraith does any of these things:

Block them.

# 🎮 GAME SECURITY

The arena is competitive.

Which means people will eventually attempt to cheat.

Somebody always does.

The game is designed around one principle:

## The browser is not the referee.

The player's browser belongs to the player.

Blindly trusting client-side information would be irresponsible.

---

# 🧠 SCORE VALIDATION

Gameplay scores should not automatically become tournament results.

Competitive scores are intended to pass through validation systems before eligibility is determined.

The validation layer exists to help identify things such as:

- Impossible gameplay
- Suspicious sessions
- Invalid submissions
- Replay attempts
- Manipulation attempts
- Automated abuse

The goal is simple:

If somebody wins...

they should have actually won.

---

# ⚠️ CLIENT VS SERVER

The client can:

- Play the game
- Display information
- Submit results

The client should not:

- Determine final rankings
- Determine final rewards
- Override validation systems

Those responsibilities belong to the server-side infrastructure.

Not the player's browser.

---

# 🏆 TOURNAMENT INTEGRITY

Tournament outcomes must be determined through consistent rules.

Competitive integrity depends on:

- Score validation
- Clear ranking rules
- Transparent timing
- Deterministic tie handling
- Consistent enforcement

The arena cannot promise everyone a win.

It can promise everyone the same rules.

---

# 💰 REWARD SECURITY

Tournament rewards require additional protection.

Winning a tournament should not place reward infrastructure at unnecessary risk.

The reward system is designed around:

- Controlled access
- Isolated infrastructure
- Verifiable activity
- Auditable reward history

The objective is simple:

Reward the winner.

Protect the system.

---

# 🏦 REWARD VAULT SECURITY

The reward vault exists to support competition.

That means protecting it matters.

The reward infrastructure should be separated from:

- Public websites
- Frontend interfaces
- General user interaction

Public visibility is important.

Public control is not.

---

That includes considerations such as:

- Access controls
- Monitoring
- Logging

# 🔍 TRANSPARENCY

Transparency matters.

So does operational security.

There is a difference between:

## Transparency

Explaining how the system works.

And:

## Operational Exposure

Publishing information that makes attacking the system easier.

The arena supports transparency.

The arena does not support publishing cheat guides.

Important distinction.

# 📜 RESPONSIBLE DISCLOSURE

Finding a vulnerability is useful.

Exploiting one isn't.

The arena supports responsible disclosure.

The preferred process is:

```text
DISCOVER ISSUE
      ↓
REPORT ISSUE
      ↓
VERIFY ISSUE
      ↓
REMEDIATE ISSUE
      ↓
DISCLOSE ISSUE
```

Giving defenders time to fix critical issues protects everyone.

---
